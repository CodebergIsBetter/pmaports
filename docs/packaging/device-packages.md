(alpine-only-devices)=
## Alpine-only devices

Some devices have an architecture that postmarketOS does not build binary
packages for. The ARMv6 Raspberry Pi Zero / Zero W (`armhf`) is the example
this was built for: Alpine still builds `armhf`, postmarketOS does not.

Such a device package sets `deviceinfo_alpine_only="true"`, which makes
`pmbootstrap install` produce a pure Alpine Linux rootfs:

* only Alpine's binary repositories end up in `/etc/apk/repositories`, and only
  Alpine's signing keys in `/etc/apk/keys` (plus the local key used to sign the
  device package itself),
* no postmarketOS package is installed. `postmarketos-base`, the
  `postmarketos-ui-*` meta packages, their providers and `_pmb_recommends` are
  all skipped, and `alpine-base` is installed instead,
* the initramfs is generated with Alpine's `mkinitfs` instead of
  `postmarketos-mkinitfs`, so there are no `postmarketos-mkinitfs-hook-*`
  packages either,
* `/boot/cmdline.txt` is generated by pmbootstrap rather than by `boot-deploy`
  (which is a postmarketOS package), from the `/usr/lib/kernel-cmdline.d/`
  fragments plus the root partition UUID,
* OpenRC is forced as the service manager, since systemd lives in
  postmarketOS' `extra-repos/systemd`,
* no pmaports package other than the device package itself is built. This
  matters because pmaports packages would otherwise win over their Alpine
  counterparts through `provides=`, e.g. `postmarketos-base` has
  `provides="alpine-base=1000-r0"`.

Consequences for the device package:

* every entry in `depends` must be an Alpine package, and `postmarketos-base`
  must *not* be one of them (pmaports CI enforces both),
* things that `postmarketos-base` normally provides have to be handled by the
  device package. In particular `alpine-baselayout` ships empty
  `/etc/runlevels` directories, so the `$pkgname-openrc` subpackage has to
  populate them, and `mesa-dri-gallium` has to be depended on directly
  instead of relying on the `install_if` in `postmarketos-base`,
* `pmbootstrap` builds the device package inside a QEMU chroot when no
  `gcc-$arch` cross compiler exists, which is the case for `armhf`.
